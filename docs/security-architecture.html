신뢰 경계

누가 무엇에 닿을 수 있는가

CUBE는 인터넷이 아니라 학교 내부망에서만 쓰는 폐쇄형 프로그램이다. 학교 방화벽이 외부 접근을 차단하고, 그 안에서만 교사 PC와 서버 PC가 통신한다.

인증

로그인 시 발급되는 세션 토큰

예전에는 클라이언트가 스스로 밝힌 사용자 ID를 서버가 그대로 신뢰했다. 브라우저에서 값만 조작하면 비밀번호 없이도 다른 계정으로 위장할 수 있었다는 뜻이다. 지금은 로그인에 성공했을 때 서버가 발급한 세션 토큰만 신원의 증거로 인정한다.

알려진 한계. 세션이 메모리에만 저장돼 있어 서버 재시작 시 전원 재로그인이 필요하다. 추후 세션 영속화로 해결할 예정.

접근 제어

관리자 화면은 조건 두 가지를 동시에 만족해야 열린다

세션 토큰이 관리자 권한을 가졌더라도, 요청이 서버 PC 밖에서 왔다면 차단한다. 실제로 교사 PC에서 관리자 세션 토큰으로 접속을 시도했더니 차단됐고, 서버 PC 앞에서 시도하니 정상 처리됐다.

XSS 방어

공지 제목에 스크립트를 삽입할 수 있었던 취약점

공지 제목을 이스케이프 없이 화면에 그대로 렌더링하는 곳이 있었다. 제목에 스크립트를 삽입하면, 그 공지를 받은 모든 교사의 화면에서 그대로 실행됐다(저장형 XSS). 지금은 DOM에 삽입하기 전 특수문자를 전부 이스케이프 처리한다.

Before · cube-widget.js
<div class="cw-item-title">
  ${n.title}
</div>
After
<div class="cw-item-title">
  ${escapeHtml(n.title)}
</div>
동일한 패턴이 교사명, 그룹명, @멘션 자동완성 등 총 다섯 곳에 더 있어 전부 이스케이프 처리했다.
